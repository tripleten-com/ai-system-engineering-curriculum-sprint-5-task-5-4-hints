# Step 1: Map one run of your graph

## Your well-behaved script ends `refused`, not `finished`

<details><summary>Hint 1</summary>

Which script did you run? Read its first entry. What does your graph do today with that kind of proposal?

</details>

<details><summary>Hint 2</summary>

Which of your scripts holds a single entry the graph can complete today? Map that run, and note in your evidence note which script you used and why.

</details>

## The map has more steps than the script has entries

<details><summary>Hint 1</summary>

What does one printed step stand for: one proposal, or one node's run? How many nodes run for one proposal?

</details>

## Your dev command doesn't print the edge's value

<details><summary>Hint 1</summary>

Which condition in your rule produced the value after each `act`? Can you name it from the status the run printed?

</details>

<details><summary>Hint 2</summary>

If you'd rather see it than work it out, what would your dev command need to read from each step to print it?

</details>

## The exception's state didn't change after the run

<details><summary>Hint 1</summary>

Which code in your graph writes to the exception record? If none does, what should its state be after the run?

</details>
